# CLAUDE.md — Bullet-Hell Game

Living architecture contract. Update at the end of every session: what's real (built and verified) vs. still open.

## What this is
Keyboard-only bullet-hell. The player dodges as a soul inside a box (Undertale-style dodging only, no ACT/menus in battle). A UCN-style roster: the player sets each character's level 0–20 and all active characters attack at once. Geometric/minimal art. Personal hobby project.

## Stack
- TypeScript (strict), Phaser 3, Vite
- No physics engine: collision is hand-written shape math in `src/combat/Collision.ts`
- Vitest for pure logic; rendering verified in the browser
- Save: versioned JSON in localStorage
- Build gate: `npm run build` must pass (not just `tsc`)

## Commits
- Every commit must build and pass tests on its own (`npm run build` and `npm test` on exactly the staged tree). Order commits so dependencies land first. Check by exporting the index to a scratch folder (`git checkout-index -a --prefix=<dir>/`, add a `node_modules` junction, then test and build there). Don't use `git stash --keep-index`: with a partially staged file its pop conflicts, and once that let a broken commit through. (Phase 3's first commit did not build; don't repeat that.)

## Commands
- `npm run dev`: dev server
- `npm run build`: production build (the gate)
- `npm test`: Vitest

## Architecture rules
1. Characters never import or reference each other. They communicate only through typed events on `core/EventBus.ts` (one bus per World, `world.bus`). Events so far: `attackStarted` (Character base, every character), `beamFired`, `beamRefracted`, `prismPhaseChanged` (Prism), `mortimerPhaseChanged` (Mortimer), `ulyssesPhaseChanged` (Ulysses), `wardenPhaseChanged` (The Warden), `emberPhaseChanged` (Ember), `stepped` (World, every step after bullets move, before hits; for combo rules), `comboTriggered` (interactions), and `boxResized`, `boxMoved`, `boxRotated`, `boxScaled` (on each request, with target and duration), `boxLanded` (a tossed box back at full size; BattleView shakes on it), `wallStateChanged`, `wallHit` (Box/World), `abilityUsed`, `abilityDenied` (World, active ability). Every event and its payload is declared in `GameEvents` there; add new events to that interface, never use untyped strings. Handlers run synchronously on emit. Combos live only in `director/interactions.ts`, so adding a character never edits existing ones. **New combos are Ian's to design**: none were added with Ember or the toss.
2. The Box is the coordinate frame. Bullets store box-local positions; `Box.toWorld` / `toLocal` convert. **Bullets are world-fixed:** when the box moves, turns or (anchored) resizes, `World.keepBulletsWorldFixed` re-expresses every active bullet in the new frame (position, velocity, rotation), so a shoved or spun box runs into attacks already in flight. The soul and props ride the box. Hooks that pin a bullet to the box (Ulysses' axe pivot, The Warden's fists) re-pin it each step.
   - **Follow-the-box rule:** every spawn, aim and gold-forming position is computed against the box as it is when the shot FIRES, not when it was planned (Prism rays recompute their path in `fire`; rows use `line` at fire time). Rows along a turned edge sample the whole edge for their off-screen offset (`edgeOffscreenOffset`), since a row's middle can cut across a screen corner. Spawns that would form in a HUD band while the box is displaced are moved (Ulysses: another edge or corner, `spawnClear`) or skipped. `combat/bands.ts` holds the shared geometry (`bulletWorldAabb`, `aabbInBand`, `PLAY_TOP`/`PLAY_BOTTOM`, `rotatedHalfExtents`).
   Box API (`core/Box.ts`; all motion advances in `box.step(dt)` on the fixed step, never Phaser tweens, so it is frame-rate independent and freezes on pause):
   - `resizeTo(w, h, duration, ease, anchor = 'center' | wall)`, `squeezeWall(wall, amount, duration, ease)` (the opposite wall stays fixed), `moveTo(x, y, duration, ease)`, `rotateTo(rad, duration, ease)`, `rotateBy(delta, ...)`, `setWall(wall, { damaging, damage, type })`, `reset()`, plus `state`, `defaults`, `walls`, `moving`, `distanceToWall`, `dirToLocal`.
   - `scaleTo(scale, duration, ease)`: the toss scale (`box.scale`, 1 = on the ground), a fourth track. It multiplies width and height (and a running resize) about the center and is not clamped to the minimum size. Each step `box.contentScale` is the factor applied; World scales the soul's box-local position by it and sets `soul.scale = box.scale`, so the soul keeps its relative spot, its radius (`hitRadius = SOUL_RADIUS * scale`, drawn == hit) and its speed (walking and dash) scale with the box, and the clamp and wall push keep it inside. Bullets stay world-fixed and keep their size (the box frame itself is unscaled). A scaled box cannot split. `normalizeRotation()` drops whole turns (same frame) after a full spin.
   - Easings are monotonic only (`linear`, `quadIn`, `quadOut`, `quadInOut`, `cubicOut`, `sineInOut`), so a tween never overshoots its clamped target.
   - Minimum size `BOX_MIN_WIDTH`/`BOX_MIN_HEIGHT` (60x60, tuning.ts). Every resize and squeeze is clamped to it.
   - **Arbitration rule (for Phase 6 combos):** size, position and rotation are three independent tracks that run at the same time. A new request on a track replaces the running one, starting from that track's current value (no snapping). Position applies as a per-step delta, so it composes with the center motion of anchored resizes.
   - Anchored resizes report `box.contentShift`; World applies it to the soul (bullets are world-fixed anyway), so a squeeze doesn't drag things the wall hasn't reached.
   - **Soul-in-box defaults (Ian may change):** the soul lives in box-local space and rides with the box when it moves or rotates. Controls are screen-relative (input is rotated into box space). Every step the soul is clamped to the interior, so a moving wall pushes it inward and it can never be outside, even after an instant squeeze.
   - Damaging walls: contact means the soul is within `WALL_CONTACT_EPS` (0.5 px) of being pressed against a damaging wall. Contact goes through `soul.damage`, so i-frames and KR apply as usual. Drawn thick lime (`theme.wallDamaging` #9dff3a, chosen to be far from every projectile color), or magenta when the wall deals KR. Never red.
   - Bullet wall hooks are checked in box-local space against the current size, so they fire where the wall really is while it moves, rotates or resizes. A shrinking wall that sweeps past a bullet also counts as a crossing.
   - Each battle builds a new World, so every battle and retry starts with ONE box at its defaults (`world.home`). Pause skips the whole fixed step, so split boxes and their tracks freeze too; the battle-end freeze keeps whatever boxes there are until the Results scene (the next battle is a new World).
   - **Multiple boxes** (`core/World.ts`): `world.boxes` holds every box in play (one normally; two while The Warden has the box ripped apart); `world.box` is the **soul's box**, exactly one at any time. The soul and every bullet are stored in the soul's box frame. The soul is clamped to, pushed by and touches the walls (damaging walls included) of ONLY its own box. Every box steps its own tracks each fixed step; only the soul's box's motion is compensated for bullets (they are world-fixed, so the other boxes simply move past them). Characters use `world.box`, so spawns, aims, gold forming and Warden punches all target the soul's box, read at fire time.
   - `splitBox()`: the soul's box becomes two halves side by side along its local x (each half the width, same height and rotation, walls copied), exactly covering the old box. The soul's box is the half that contained the soul's center (x <= 0 goes left, so a soul on the split line goes left and the clamp pushes it fully inside). Refused if a half would be under `BOX_MIN_WIDTH`. Emits `boxSplit { soulBox: 'left' | 'right', gapAxis, width, height }`.
   - `mergeBoxes()`: two touching boxes become one box covering their union (measured in the first box's frame), so the merge draws no jump; the soul keeps its world position and is clamped inside. Emits `boxMerged { x, y, width, height }`. `resetBoxes()` returns to one box at `world.home`.
   - Changing the soul's box re-expresses the soul and every bullet (current and pre-step state, velocity and rotation) in the new frame (`World.reframe`), so nothing jumps and interpolation stays smooth.
   - Wall hooks: crossings of the soul's box are checked as before (hook gets no box argument). For every other box, a bullet that goes from inside it to outside it fires `onWall(b, wall, ctx, box)` with that box; 'die' removes it and 'bounce' reflects it in that box's frame. Bullets pass through the gap and the other box freely otherwise.
   - Only the soul's box is the frame for interpolation of bullets and the soul; every box is drawn through its own interpolated `BoxFrame` (BattleView keeps one per box).
3. Characters are config plus a small class. `<name>.config.ts` maps level bands to attacks, damage, speed, frequency. The class only holds behavior the config can't express. Level 0 = inactive.
   Config format (`characters/config.ts`):
   - `bands: [{ from, to, attacks: { <attackId>: { <param>: [atBandStart, atBandEnd] } } }]`, covering 1..maxLevel with no gaps.
   - `resolveLevel(cfg, level)` interpolates every param linearly within the level's band. `count` and `gapSize` round to integers. A one-level band uses its start value.
   - Every attack needs a `cooldown` (seconds between shots). Higher bands must re-list every lower attack (enforced by `validateConfig`, tested for every shipped config), so "keeps lower attacks" is explicit data. Difficulty must not drop at band edges (also tested).
   - `rules`: non-level constants (limits, sizes, design defaults).
   - `Character` (base) resolves on `setLevel`, runs one timer per enabled attack on the fixed step, and calls the subclass's one-method-per-attack map. It owns a seeded RNG so sequences are reproducible. `registry.ts` lists characters by id; the runner and Director use only `CharacterHandle`.
4. The Director owns battle time and ticks every active character's schedule. Modes (`TimerMode`, `WaveMode`) only decide when the battle ends or what loads next.
   - `director/Director.ts`: `new Director(world, roster, mode)` creates only characters with level > 0 (from `registry`), installs `interactions` for the active set, and on each `step(input, dt)` ticks characters, steps the World, advances `time`, and asks the mode. When the mode answers it sets `outcome` = `{ result: 'win' | 'loss', mode, time, hp, maxHp, roster }` and freezes.
   - `director/modes/Mode.ts`: `BattleMode { id, label, evaluate({ time, soulAlive }) -> 'win' | 'loss' | null, hud(state) -> string }`. `TimerMode(duration = TIMER_DURATION)` wins at the target time; HP 0 loses, and death wins a tie.
   - `director/interactions.ts`: the only place for cross-character combos. Each rule is `{ id, requires: [ids], install(bus, world) -> unsubscribe }`, and is installed only when every required character is active (level > 0). Rules may read character data files (e.g. `SWORD_FLAGS` from `ulysses.config.ts`) and the World, never character classes.
   - **Combos:**
     - `prism-ulysses-split` (Prism + Ulysses): on `stepped`, an active white Ulysses sword (flag `sword`, not `split`) whose center is inside a refraction prop (`Prop.refracts`) is replaced by 3 white swords from the `fan` pattern (`PRISM_SWORD_SPREAD` 0.6 rad), flagged `split`, which ignore prisms. Gold swords pass through unchanged. Emits `comboTriggered { count: 3 }`.
     - `mortimer-ulysses-blizzard-sync` (Mortimer + Ulysses): while Mortimer's phase is `blizzard`, every gold Ulysses projectile joins a group whose shared shine is the latest planned shine among them + `BLIZZARD_HOLD` (0.6 s); all their `armAt` are set to it, so they stay gold longer and shine at once. Emits `comboTriggered { at }` when the group's time is set or pushed.
   - `director/roster.ts`: a `Roster` is plain data (`{ [id]: level }`), copied between scenes, never a live object, so retry always starts clean.
5. All damage goes through `soul.damage({ amount, type })`. i-frames and KR poison are handled there and nowhere else.
6. Game logic runs on a fixed 60 Hz timestep, separate from rendering, so difficulty is frame-rate independent.
7. Collision, config lookup, damage, scheduling and battle outcome are pure (no Phaser) with unit tests. Phaser code only draws and reads input.
8. Bullets come from `BulletPool`; never `new Bullet()` inside the game loop.
9. Colors come from `render/theme.ts`. Each character owns one accent color; bullets must stay readable against the box at all levels.
10. Exact hitboxes: what you see is what hits you. Every collision shape equals its drawn shape and size. Drawing and collision both derive from the same geometry functions in `combat/Bullet.ts` (`bulletCircle`/`bulletRect`/`bulletTriangle`), and the soul's drawn radius is its hit radius. Never add a separate "hitbox size". Bullets fade into existence at full size (`Bullet.fadeAlpha`, visual only; the hitbox is full size from the first step and `scale` is always 1). Despawn fades are visual-only ghosts that never collide.
    - **Composite hitboxes** (`combat/composite.ts`): a themed projectile is `shape: 'composite'` with a `form` = primitive parts (rects, circles, triangles) in the bullet's own frame (+x = where it points, origin = position/pivot), built with `makeForm` (extent computed). `bulletPrimitives(b, fn)` yields every primitive of any bullet in box-local space; `hitTest` and `BattleView` (fill and hitbox overlay) both go through it, so each solid drawn part is exactly its hitbox, rotated and scaled with the bullet. Curves are chains of short rects (`curvedStreak`), drawn and collided the same.
    - **Rings** (`shape: 'ring'`, `a` = radius of the center line, `b` = thickness): `RING_SEGMENTS` 48 chord rects of the circle, each lengthened by (b/2) tan(pi/48) so neighbours meet at the outer edge. `bulletPrimitives` yields them, `hitTest` adds a quick distance reject, and BattleView draws each chord as the stretched line look (`LookCache.line(b)`, exact thickness), so the drawn ring is its hitbox at any radius with one texture. Used for Ember's wildfire.
    - **Decorative glow rule:** a glow (`glow: true`, `BattleView.drawGlow`: two faint wider layers around each rect part, alpha `theme.glowAlpha`) is decoration only. It never collides and the hitbox overlay never outlines it; the solid core drawn on top is what hits.
11. Visual style (in the spirit of Just Shapes & Beats): near-black background, flat bright solid shapes with crisp edges, no textures or images, thin clean lines, lots of empty space, one accent per screen. Motion is short and punchy: a fade into existence at full size on spawn (`SPAWN_FADE_TIME` 0.1 s; off-screen spawns skip it), fast fade on despawn, brief flash and small shake when the soul is hit, 140 ms scene fades.
    - Resolution: every scene lays out in a fixed 1280x720 virtual view (`VIEW` in theme.ts). `render/display.ts` sizes the canvas to the real device pixels it occupies (fit-to-container x devicePixelRatio) and each scene's camera zooms the view to fit (`applyView`, called by `enter()`). Nothing is CSS-upscaled, so it stays sharp at any window size or DPI; text is rasterised at the same scale and re-rasterised on resize. Phaser `Scale.FIT` + `CENTER_BOTH` does the centering; the `#game` container must not also center (that double-centered the canvas before).
    - Never lay out with `this.scale.width/height` (that's device pixels); use `VIEW`.
    - Typography: one UI face, Inter (self-hosted via `@fontsource/inter`, latin 400/600), and JetBrains Mono (`@fontsource/jetbrains-mono`) only for numbers (levels, timer, HP, stats). Fonts load before the game boots. Sentence case or lowercase; no all-caps labels.
    - Scales in `theme.ts`: `type` (hint 15, small 17, body 22, label 26, number 44, title 64), `space` (xs 6, sm 12, md 24, lg 48, xl 96), `line` (thin 2, box 2, danger 6). Colors: `text`, `textDim` for secondary, `textMuted` for hints, `locked` for placeholders.
    - Screen patterns: selection = full brightness plus a small red dot (menus) or a thin accent underline (roster); everything else dims. One quiet controls line at the bottom (`hint()`). No boxed cards or panels.
    - Gameplay sizes are separate from UI sizes: `tuning.ts` writes every gameplay distance, size and speed as `px(original)` with `WORLD_SCALE = 1.5` (720/480), so the game feels exactly as it did at 640x480.
12. Red belongs to the player (solid red circle). Hazards never use red. A projectile's color comes only from its type (rule 16): white, blue, orange, KR magenta. Character accents are for their non-projectile props and profile box, never projectiles.
13a. **Pre-active (gold) bullets** (`combat/Bullet.ts`, shared): `armDelay` s after spawning a bullet is pre-active: drawn in `theme.preActive` (pale gold #e9cf6a), never collides (World skips `!b.armed`), never culled for leaving the screen. When its age reaches `armAt` the pool sets `armed`, runs `onArm` once (e.g. lock-on), and from that step it collides with its type's rule and color. `growIn` fades it in at full size over its gold time, at most `GOLD_FADE_TIME` 0.4 s (visual only; there is no grow-in any more). The gold -> white moment draws a shine (`effects.drawShine`, `SHINE_TIME` 0.12 s): a local burst at the bullet, a gameplay cue that lives in the effects file but is deliberately not gated by the hit-flash setting. `armAt` may be changed while pre-active (combos do). Despawn ghosts keep the bullet's state (a gold bullet fades gold).
13. Characters customise bullets through `onStep`/`onWall` hooks and compose `combat/patterns/` (line, fan, ring, aimed), not through Bullet subclasses or hand-written spawn loops.
14. Render interpolation: logic and collision use the simulated state; drawing uses the interpolated state. `World.step` first calls `world.snapshot()` (box, soul and every active bullet record `prev`/`px,py,prot`), and `BattleView.draw(realDt, alpha)` blends prev -> current by `clock.alpha` (leftover step fraction) through `render/interp.ts` (`BoxFrame`, `lerpPoint`, `lerpAngle`). Never read `prev` in game logic. Spawns and resets start with prev == current; a jump over `SNAP_DISTANCE` or a turn over `SNAP_ANGLE` in one step draws at the current state (teleports, bounces). Pause holds alpha still (no jump); a frozen battle re-snapshots so it draws its final state. The hitbox overlay forces alpha 1, so with it on, drawn shapes are bit-identical to collision shapes. New moving things must add their state to `snapshot()` and draw through the blend. Never change game speed with rAF tricks: game time comes only from the fixed step.

## HUD bands (layout rule)
- The battle HUD lives only in two bands, `hud` in `render/theme.ts` (1280x720 layout): **top** y 0-120 (timer at y 40, roster summary left, pause right, 44 px profile row centered at y 94) and **bottom** y 618-720 (HP and ability bars at y 650, controls hint at y 696). The box (x 415-865, y 204-534) stays centered between them.
- **Rule: no attack may spawn or form (pre-active stage) inside a HUD band.** Bullets may pass through. Measured at level 20: everything spawns fully off screen except refracted rays (at the refraction prism, beside the box, clear of the bands) and Ulysses' gold forming (x 340-940, y 129-609). `render/hudBands.test.ts` runs all five characters at 20 for 40 s (covering a toss and a split) and requires 0 spawns and 0 gold steps in a band; extend it when adding a character.
- Bullets draw over the HUD: battle HUD text, bars' labels and profile boxes are DOM in the **under-layer** (`UiLayer`, a second root below the canvas); the battle camera clears transparent (the game is created with `transparent: true`; every other scene's camera still clears to the background). Only the clickable pause button and the pause menu sit above the canvas. HUD elements are thin, never filled panels.
- HP bar is mint `theme.hpFill` #4fe3a0, away from every projectile and form color (white #f4f4f8, blue #2aa0ff, orange #ff8a1c, KR #ff2bd6, gold forming #e9cf6a), Ulysses' gold #f2c230, damaging-wall lime #9dff3a and the player's red #ff2a4a (tested: RGB distance > 100 from each). Ability bar ready is light grey #b8b8c8 (not projectile white).
- Dev: B in battle toggles `view.showBands` (magenta shading of the bands; `__battle.view.showBands`).

## Rendering and performance
- **Sprites from a texture cache** (`render/LookCache.ts`, `BattleView`): every bullet look is rasterised ONCE into a white canvas texture at the current render resolution (`k` = renderScale texels per layout px) and drawn as pooled Phaser images (`SpriteLayer`, one per depth) that are positioned, rotated, scaled and tinted each frame. Bullets are not clipped to the box (attacks are seen arriving from off screen).
  - A look is drawn from the same primitives collision uses (`bulletPrimitives` on a template bullet at the origin, rotation 0), so the solid sprite is the hitbox shape. Composite parts are filled as one nonzero path (overlaps never double up).
  - **Prewarming:** each character's `lookSpecs()` lists every look it can draw at its level (shapes, forms, glows, snowball radii, shines, decor, the prism prop). `BattleScene` passes them to `view.setPrewarm` right after building the Director, behind the scene fade, and `prewarm()` runs again whenever the render scale changes. Shine rings are cached per radius bucket (powers of `RING_BUCKET` 1.04; the sprite scales to the exact radius). Measured: 59 looks prewarmed and 0 built during 40 s with all four at 20 (`view.looks.built - view.warmBuilt`). A new character must list its looks in `lookSpecs`.
  - **Decor bullets** (`decor: true`, `tint`): drawn objects that never collide (World skips them), are never outlined by the hitbox overlay and are not attacks for the HUD-band rule. Drawn on the prop layer as a fill tinted `tint` plus an outlined edge look (`LookCache.edge`). Used for The Warden's fists. Despawn reason `'cancel'` removes a bullet with no ghost.
  - Look keys: `circle` by size bucket (radius rounded UP to powers of 1.15; the sprite scales down to the exact radius, so growing snowballs reuse a few textures), `beam`/`rect`/`triangle` by their size fields, composites by form identity. Color is the tint (gold vs white is just tint), alpha is sprite alpha (times the fade-in, `fadeAlpha`).
  - Other cached looks: the soul and dash trail (disc), refraction props (fill + outline), shines (disc + ring per 0.5 px radius), walls (a short texture with exact anti-aliased long edges, stretched along each wall), and ray glows (the two glow layers pre-composited into one texture per beam size; decorative, drawn on a lower layer, never part of the hitbox).
  - **Adding a new look:** nothing to register. Any bullet (any shape or composite form) is cached on first draw; a new kind of non-bullet decoration gets a builder in LookCache and a SpriteLayer at the right depth. Keep forms long-lived (module constants or cached per size) so their identity key is reused.
  - Resolution changes: `looks.sync(renderScale())` each frame; when the scale changes (quality setting, devicePixelRatio, window size) every texture is removed and rebuilt on demand at the new scale, and pooled images are re-pointed at `__DEFAULT` first (they would otherwise keep the destroyed textures; that crashed once).
  - Still Graphics: the box fill (axis-aligned under the walls), the HUD bars, and the dev overlays. The hitbox overlay strokes the true collision primitives directly, so it still proves sprites match hitboxes.
  - **No canvas MSAA** (`antialiasGL: false` in main.ts): rotated and curved shapes are pre-anti-aliased textures, and 4x MSAA of the full-resolution backbuffer was the largest per-frame cost (3.5 ms median at 3214x1808 with nothing drawn). `antialias: true` keeps linear texture filtering.
  - Measured edge accuracy (sprite 50% coverage vs exact hitbox boundary, perpendicular, device px, at zoom 2.51): p50 0.06-0.18, p99 0.22-0.49 for circles, rays, volley triangles, gusts, gold swords and the axe; the rare larger readings were next to another edge within 1-2 px (overlaps, thin tips) where pixel coverage mixes.
- F3 toggles the performance overlay in every build (`ui/PerfOverlay.ts`, stats in `render/frameStats.ts`): fps, display frame interval, steps per frame, CPU frame time (median/p99/max) with a 120-frame graph (guides at 8.3 and 16.7 ms), dropped frames (interval over 1.5x median), bullets, devicePixelRatio. `window.__perf` exposes it. Frame time is CPU-side; GPU stalls show as longer intervals.
- Benchmark method (the automation browser throttles rAF to ~13/s): sleep `game.loop`, then call `game.step()` in a tight loop with `__battle.loop.last` set one step back (one sim step per frame) and `gl.readPixels` of 1 px after each frame to include GPU time. To test frame caps, call the wrapped `game.loop.callback(t, tickMs)` with busy-waited ticks instead (that goes through the limiter).

## Controls
Arrows/WASD move, **Space** = slow movement (`SLOW_MULTIPLIER`), **Shift** = use the equipped active ability, Esc = pause. `main.ts` prevents the default for Space and arrows on every screen, so the page never scrolls. Shift is latched on keydown in `FixedLoop` and handed to exactly one fixed step as `MoveInput.ability` (key repeat ignored; cleared on resync after pause). Space no longer selects in the pause menu (Enter does).

## Abilities and loadout
- `abilities/Ability.ts`: `ActiveAbility { id, name, cooldown, remaining, ready, active, activate(world, input) -> 'used' | 'notReady' | 'noop', step(world, input, dt) -> movedSoul }`. `CooldownAbility` handles the cooldown; only 'used' spends it. World holds `world.ability`; each step it calls `activate` when `input.ability` is set (emitting `abilityUsed` or `abilityDenied`), then `step`; if `step` moved the soul, normal movement is skipped. The box clamp runs after either way.
- `abilities/loadout.ts`: `Loadout { active: id | null, passive: id | null }`, plain data like the roster. `DEFAULT_LOADOUT` = dash + no passive. `ACTIVES`/`PASSIVES` registries by id (passives empty). Stored under its own key **`ubg.loadout.v1`** (`{ v: 1, active, passive }`), separate from settings; parse falls back field by field, storage never throws. BattleScene equips `createActive(loadLoadout(...))` into each new World. Nothing writes the loadout yet; the Phase 8 shop will (`saveLoadout`).
- Dash (`abilities/actives/Dash.ts`, tuning in `tuning.ts`): `DASH_DISTANCE` = default box width / 3 = 150 px, `DASH_DURATION` 0.12 s (1250 px/s, ~20.8 px per step, under `SNAP_DISTANCE` 60, so it interpolates as smooth motion; threshold unchanged), `DASH_COOLDOWN` 3 s (from use), `DASH_IFRAMES` = the duration (max'd with running i-frames, never shortens them). Direction is the held input, screen-relative, fixed at activation. No direction = nothing spent. Clamped every step, so it stops at walls and squeezes push it.
- HUD: the ability bar sits right of the HP value in the bottom HUD band (`BattleView.abilityBar`), drawn only from the interface: fill = 1 - remaining/cooldown, dim (`theme.abilityCharging`) while recharging, bright (`abilityReady`) and a pop on the label when ready. `abilityDenied` flashes the empty bar and nudges the label. The dash trail is 6 translucent soul-red circles from the dash start to the soul, fading over `DASH_TRAIL_FADE` (visual only).

## Settings
16. **Projectile types** (`combat/projectile.ts`, the only place hits are decided). Every bullet has `kind` (default white): **white** hurts on contact; **blue** hurts only while the soul is moving; **orange** hurts only while the soul is still; **kr** hurts on contact and deals KR. "Moving" is `soul.moving`: a direction is held this step (set in `Soul.move` before collision; opposite keys cancel to still), or a dash is running. Pressing into a wall counts as moving (so blue can't be dodged by hugging a wall); riding the box doesn't count. A non-hurting contact passes through with no damage and no i-frames; hurting contacts go through `Soul.damage` (`damageTypeOf(kind)`). Colors are fixed in `theme.bullet`: white `#f4f4f8`, blue `#2aa0ff` (shifted toward cyan from #2e8bff), orange `#ff8a1c`, kr `#ff2bd6`. DebugScene key 9 spawns one of each.
17. **Off-screen spawns.** Edge attacks start beyond the 1280x720 screen (`SCREEN_WIDTH/HEIGHT` in tuning) and travel in (`combat/offscreen.ts`: `exitDistance`, `edgeOffscreenOffset`, `offscreenStart`; `line()` defaults to just off screen). Exceptions: Ulysses' gold swords form on screen just outside the box (the gold stage is the warning); Ember's wildfire rings form just outside a wall of the box (outside it, clear of the bands) and grow across it, as the spec asks. **Edge-based despawn:** an active bullet goes only once its WHOLE shape (world-space center ± its extent at current scale, `BulletPool.offScreen`) is outside the screen *and* it is not heading toward the box, or past `FAR_CULL_DISTANCE`. Inbound bullets are never culled, nothing vanishes while partly visible, and bullets that leave the box but are still on screen keep flying. (Replaces the old center + `DESPAWN_MARGIN` rule.) Entering the box never fires wall hooks; only inside -> outside does. Off-screen spawns skip the fade-in (it would happen out of view).
18. **Arrival timing and attackStarted** (first arrivals: an attack's first plan is pre-fired; shots whose lead is longer than the time left spawn immediately, already advanced along their straight path, so the opening arrives on time: first arrival `FIRST_SHOT_DELAY` = 1.0 s, staggered 0.6 s per attack; later plans still shift). (`characters/Character.ts`). An attack's timer counts down to when it should reach the box. An attack either acts immediately (returns nothing) or returns `Shot[]` (`{ lead, fire }`, where lead = off-screen travel time). The base plans `planAhead()` seconds early and fires each shot at arrival - lead, so off-screen attacks keep their old beat. When a lead is longer than the time left (battle start), that arrival and the rest of the attack's schedule shift later instead of bunching up. The base emits `attackStarted { owner, attack }` when an attack's first projectile spawns (or when a no-projectile attack runs). The battle screen's profile boxes light on it, so every character gets this for free.
15. **Settings never touch the simulation.** They only change how and how often the game is drawn (frame limit, render quality, overlay, screen effects). The fixed 60 Hz step, timing, difficulty and hitboxes are identical under every setting. Never read settings from game logic (`core/`, `combat/`, `characters/`, `director/`).
- Data: `settings/settings.ts` (pure): `{ frameDivisor, quality, showFps, shake, flash }`. Stored in localStorage under its own key **`ubg.settings.v1`** as `{ v: 1, ... }`, separate from game progress (Phase 8 gets its own key). Missing, corrupt, wrong-version or invalid fields fall back to defaults field by field; every storage access is in try/catch. Defaults: match display, full, FPS off, shake on, flash on. A corrupt stored value is left alone until the next change overwrites it.
- Live store: `settings/store.ts` `settings.current` / `set(patch)` / `reset()` / `onChange`. Every change saves immediately. `main.ts` refits the canvas on quality changes and pins the perf overlay on showFps. `window.__settings` exposes it in every build.
- Refresh rate and frame limit: `render/frameLimiter.ts` wraps Phaser's loop callback (it intercepts `loop.start`, because Phaser emits `ready` before starting the loop). Every display tick feeds the refresh estimate: median interval, snapped to a common rate within 2% (`settings/refresh.ts`), 30-tick startup sample, then 120-tick windows. It updates on a >5% change seen in two windows in a row, re-samples on a pixel-ratio change (new screen), and ignores <30 Hz samples (throttling). Caps are refresh/N for N=1..4 while >= 30 fps (144 Hz: 144/72/48/36). The stored value is the divisor N, clamped to what the display offers. On a non-drawn tick the whole Phaser step (input, update, render) is skipped and its delta is carried to the next drawn tick, so Phaser timers keep real time. Draw gating uses the vsync rAF timestamp, not `performance.now()`: a draw happens once (N - 0.5) ticks have passed. FixedLoop still runs fixed steps from real time, so the sim stays at 60 steps/s and interpolation covers any cap.
- Render quality: `qualityCap()` caps the ratio used by `display.ts` `computeScale` (full = devicePixelRatio, balanced = at most 1.5x CSS, performance = 1x). `refit(game)` applies it live and re-points cameras of running and paused scenes. The DOM UI is unaffected, so text stays sharp.
- Screen effects: anything that shakes or flashes the screen calls `render/effects.ts` `shakeScreen` / `flashScreen`, the single gate for the shake and flash toggles. Never call `cam.shake` / `cam.flash` directly.
- Screen: `scenes/SettingsScene.ts` (HTML layer). It opens from the menu (`go`, Back returns to the menu) or from pause, where Battle is `scene.pause()`d and Settings is launched over it (Settings is last in the scene list). Back resumes Battle, which re-shows its HUD and pause menu and stays paused. Rows: label, then ‹ value ›. ↑/↓ choose, ←/→ change, Enter steps or activates, Esc/Backspace back, hover selects, clicks on the row or arrows change values. A quiet line shows the measured refresh rate and canvas size.
- Keyboard queue fix (`main.ts`): Phaser processes its whole keyboard queue on every DOM key event but only empties it once per game step, so two presses in one drawn frame replayed the first. A window listener added on `ready` (after Phaser's) empties it after each event.

## Pixel ratio and HTML UI layer
- Pixel-ratio rule: the canvas backing store is always displayed CSS size x devicePixelRatio (`render/display.ts`); re-fit on window resize, host resize and ratio changes (matchMedia). The camera maps the 1280x720 layout onto it. Dev-only `?dpr=1.5` fakes the ratio for testing.
- All UI text (menu, roster, HUD, pause, results) is DOM in `src/ui` (UiLayer + styles from theme tokens), not Phaser text, which blurred under fractional zoom with LINEAR filtering. The overlay copies the canvas rect exactly. Only the dev DebugScene still uses Phaser text.
- Input rules: scenes own state; the DOM only renders and forwards input. Hover and keyboard share one selection index per screen. Mousedown and wheel are prevented on the overlay, so clicks never take focus or scroll the page. Locked items use a not-allowed cursor and ignore the mouse. Battle movement stays keyboard-only; a quiet "pause" button gives a mouse route.

## Scene flow
`Menu` (Timer mode; Wave mode shown as coming soon; Settings) → `Roster` (5 UCN-style slots, all five launch characters real: Prism, Mortimer, Ulysses, The Warden, Ember; ←/→ pick a slot, ↑/↓ change level, Z sets all to 0, X sets all to 20, Enter fights, Esc returns to the menu; shows total difficulty) → `Battle` (Director + TimerMode; HUD shows the countdown, HP/KR bar and roster summary; Esc pauses: resume / settings / restart / quit to roster) → `Results` (win/loss, time survived, HP left, levels; R or Enter retries the same roster, Esc goes to the roster with levels kept).
Transitions are 140 ms fades (`SCENE_FADE_MS`) via `scenes/ui.ts` `go()`/`enter()`, and every screen follows the visual rules (rule 11). While a screen fades out it ignores input: `go()` switches the leaving scene's keyboard off and the DOM screen gets `.leaving` (no pointer events). `enter()` switches the keyboard back on, because the plugin outlives restarts.
Battle HUD: profile boxes, a centered row of 44 px boxes directly below the timer in the top HUD band, one per active character with its shape in its color (icon at 55% opacity). **Profile flash rule:** on that character's `attackStarted` only the box border and the icon light (border to the accent, icon to full opacity) and fade back over 450 ms. The box never has a fill, so bullets drawn under the row never change color. Pause skips the fixed step and `FixedLoop.resync()` on resume, so no time is caught up.

Dev shortcuts:
- `?roster=prism:12` (comma-separated `id:level`, clamped, unknown ids ignored) skips the menu straight into battle. It applies once per page load and works in production too.
- `?duration=<s>` shortens timer mode. Dev builds only; it's stripped from production.
- In dev: H toggles the hitbox overlay; backtick opens DebugScene.
- Every build: F3 toggles the performance overlay.

## Characters
### Prism (cyan triangle): pure dodging, no box effect
- The refraction prism is light violet `theme.prismProp` #b49cff (distinct from blue projectiles). It is world-fixed: placed beside the box clear of the bands, it stays put when the box moves, and is re-placed (on the other side if needed) if the box covers it. The opening volley (pre-fired) comes from a side, so it never appears in a HUD band.
- Files: `characters/prism/prism.config.ts` (all numbers, phases and rules) and `Prism.ts`. Accent cyan is its profile box and the refraction prism; every projectile is `kind: 'white'`, including refracted rays.
- **Phases** (every level 1-20, all as data in `rules`): `phaseOrder` wall -> ray, each `phaseLength` 8 s, with a `breather` of 1 s between phases where nothing new reaches the box. Inside its phase every attack runs at `phaseIntensity` = 2x its band's rate (cooldown / 2). `attackPhase` maps volley -> wall, beam and prism -> ray; an attack's arrivals only fall inside its own phase window (`Prism.nextArrival`, a generic `Character` hook). Off-screen shots for the next phase may spawn during the breather (out of view); arrivals don't. Timeline: wall 0-8, breather 8-9, ray 9-17, breather 17-18, wall 18-26, ... Battles start in the wall phase; the first volley reaches the box at 0.98 s (pre-fired, rule 18).
- `prismPhaseChanged { owner, phase: 'wall' | 'ray' | 'breather', next }` on every change (for future combos). Profile boxes still light on `attackStarted`; a skipped prism relocation returns `null` and lights nothing.
- Wall phase, `volley`: a row of white triangles (pointing along travel) from one edge, never the same edge twice in a row, starting off screen. Constant `volleySpacing` 33 px, as many as fit (13 top/bottom, 10 sides), one safe gap of `gapSize` slots (5 -> 3 L1-5, 3 -> 2 L6-14, 2 L15-20). Base cooldown 2.6 s (L1) to 1.0 s (L20), so 1.3 to 0.5 s in phase.
- Ray phase, `beam`: light rays, a solid white core (length 45-60, thickness 6; the hitbox) with a faint decorative glow, crossing a random point on a random box edge at up to +/-20 degrees off the inward normal, starting off screen. Aimed rays (`aimChance`) enter through the wall facing the prism: their line runs from off screen through the prism to that wall point, so they fan into three before entering. Speed 330-382 px/s (L1-5), 390-540 (L6-14), 540-600 (L15-20). Count 1 -> 3. Rays have no wall hook: they never split.
- Ray phase, `prism`: a large translucent violet triangle (radius 42; 18% fill, outline) that stands only OUTSIDE the box: beside its left or right wall (gap `prismGap` 18 px past its radius, up to `prismSpread` 105 px farther out), inside the screen and clear of the HUD bands, where aimed rays pass. It appears at the start of the breather before each ray phase (a telegraph) and is removed when the ray phase ends; it relocates once it has stood a full (phase) cooldown (10 s -> 6 s base). `aimChance` 30-70% of rays aim through it (re-aimed when they spawn). A ray whose center enters it becomes exactly `refractCount` = 3 rays (gen 1, REFRACTED flag) fanned by `refractSpread`; refracted rays ignore prisms. They start at the prism (on screen, outside the box), the one exception to off-screen spawns besides Ulysses' gold forming. DESIGN DEFAULT: the prism is harmless (`prismHarmless`).
- Never easier as level rises: tested per parameter (damage, speed, count, length, aimChance, refractSpread up; cooldown, gapSize down) across 1-20.
- Emits `beamFired` (gen 0 original, 1 refracted), `beamRefracted` (count), `prismPhaseChanged`; the base emits `attackStarted`. `beamHitWall` was removed with splitting; the generic bullet `onWall` hook stays (DebugScene key 6 still demos a split).

### The Warden (orange stone golem): support character who moves the box
- **Support rule (still harmless):** his fists and hands are decor objects (never collide, never inside the box, damage 0). His danger is moving the box into other characters' world-fixed attacks. Alone he deals zero damage (tested still and moving at L1/10/20).
- Files: `characters/warden/warden.config.ts` (bands, rules, `FIST_FORM`, `FIST_DEPTH`) and `Warden.ts`, same shape as the others. Registry slot 4 (`shape: 'golem'`), accent `theme.warden` #ff9b3d (roster and profile). Fists are `theme.wardenFist` #8f4519 with a lighter edge, `wardenFistEdge` #e0874a. `?roster=prism:15,mortimer:15,ulysses:15,warden:15` works.
- Phases: punch -> toss -> rip, 8 s each with 1 s breathers (`phases.ts`), emitting `wardenPhaseChanged`. Punch windows close early by back + shove + linger, toss windows by the whole toss (`tossTail`), rip windows by `ripTail`. No opening pre-fire.
- Punch (1-20): a fist forms `fistGap` outside the middle of a wall, draws back `fistPull` over the wind-up (0.9 -> 0.4 s), lunges in `lungeTime` 0.08 s (the impact is the beat), and the box slides `distance` (120 -> 345 px wanted) with `Box.moveTo` (`shoveTime` 0.32 s, cubicOut), the fist riding the wall. `back` s (1.6 -> 0.6) after the impact, a fist from the opposite wall punches it home (`box.defaults`). Vertical with chance 0 -> 0.5. Shoves are clamped (`shoveRoom`) so the turned box outline stays on screen and between the HUD bands, with room left for the return fist; a direction with under 35% of the wanted shove switches to the other side. Vertical room is small (the box has ~84 px each way and a fist needs ~65), so vertical shoves are about 20 px.
- Toss-and-spin (6+, attack id `toss`; replaced the old limited swing): rocky hands (`HAND_FORM`) form outside the left and right walls, wind up (0.8 -> 0.5 s) and grab. While small it spins whole turns (`turns` 1 -> 3, rounded, at `speed` 3.2 -> 6.4 rad/s, quadInOut); with chance `reverse` (0 -> 0.5, 2+ turns) it turns back part way, still ending on a whole number of turns. Then it lands: scales back to 1 (quadIn over `fallTime` 0.35 s), whole turns are dropped (`normalizeRotation`) and `boxLanded` makes BattleView shake (`LAND_SHAKE_MS` 140, intensity 0.01, through the effects gate). The soul and its radius scale with the box, so it stays inside at the same relative spot. Never starts while split (and a tossed box can't split). Cooldown 7 s: one toss per phase.
- Rip apart (15+, attack id `rip`, its own phase after the toss): rocky hands (`HAND_FORM`, decor like the fists) form outside the left and right walls, wind up (0.7 -> 0.5 s) and grab: the box splits (`world.splitBox`) and each hand pulls its half outward by half the `gap` (105 -> 180 px) over `pullTime` 0.35 s, clamped (`pullRoom`) so each half and its hand stay on screen. The soul stays in the half it was in. After `hold` (2.5 -> 3.5 s) a fist punches one half into the other (the left half pushed right; with chance `either` 0 -> 0.5 the right half pushed left) over `mergeTime` 0.3 s (quadIn); once the punched half stops, the two merge into one 450x330 box, offset from center by half the gap. `back` s (0.9 -> 0.6) later a fist on the far side punches it home (`world.home`). The rip's window closes early by the whole sequence (`ripTail`), so it finishes inside its phase; cooldown 7.5 -> 7 s means one rip per phase.
- The halves keep the box's height and y, so they stay between the HUD bands; the merge happens where the halves already are, so every intermediate box is on screen.
- Punch returns and re-centers go to `world.home` (a merged box's own `defaults` are off center).
- DebugScene: `,` punch (with its return), `/` toss, `[` rip apart, `]` merge punch (left half into the right), `\` re-center (level 20 params; The Warden ticks at level 0 for these). The box keys act on the soul's box; Z resets to one default box.
